# Vercel (current setup)

The project is already linked (`.vercel/project.json` → project `bujo`). Vercel detects Vite, builds `dist/`, serves the SPA, and runs `api/*` as serverless functions automatically.

## Deploy

**The CLI has to be logged in, and a fresh machine is not.** `vercel whoami`
answers `Logged out` and every deploy command then fails or silently offers a
throwaway deployment instead of the real project. The login is a device flow —
it opens a browser and waits — so it cannot be done by an agent or in CI:

```bash
npx vercel whoami        # expect an account name, not "Logged out"
npx vercel login         # device flow, opens a browser
```

For CI or a non-interactive session, mint a token at
<https://vercel.com/account/tokens> and pass `--token=$VERCEL_TOKEN` to every
command instead of logging in.

Then:

```bash
# preview
vercel
# production
vercel --prod --yes
```

Git integration also auto-builds on push. **Note:** the human-facing alias
`bujo-journal.vercel.app` does NOT auto-follow new prod deploys — re-point it
each time:

```bash
vercel alias set <new-deploy>.vercel.app bujo-journal.vercel.app
```

`scripts/ship.sh --deploy-only` does the build, the deploy and the re-alias in
one step, which is the whole reason it exists.

**Anything that rewrites `node_modules` takes the browser gates with it** —
`vercel build`, and equally an ordinary `npm install` or `npm uninstall`.
Measured twice in one session: once after a deploy, once after removing a single
dependency. `playwright` and `@axe-core/playwright` are deliberately NOT in
`package.json` — `.github/workflows/a11y.yml` installs them with `--no-save` so
they never reach a user's bundle — which means a local install of them is
untracked, and the install `vercel build` runs removes it. After a deploy,
`npm run a11y` and `npm run clipped` fail on `Cannot find package 'playwright'`,
which reads like a broken gate rather than a missing package:

```bash
npm i -D --no-save playwright @axe-core/playwright
npx playwright install chromium          # the browser binary too, if it was pruned
```

Do this BEFORE concluding anything about a gate that started failing right after
a deploy.

## Confirm what you deployed · do not skip this

A deploy can succeed while the alias still points at the previous build, so
"the command exited 0" is not evidence that anyone can see your change. The
page states its own identity — check it:

```bash
curl -s https://bujo-journal.vercel.app/ | grep -o '<title>[^<]*</title>'
# expect: <title>Cadence Journal — habits, training and how you actually felt</title>
```

If the title is the old one, the deploy landed and the alias did not follow.
This is not hypothetical: the demo served `bujo — minimal bullet journal` for a
full session of merged work, and the bundle hash was the giveaway:

```bash
curl -s https://bujo-journal.vercel.app/ | grep -oE 'assets/index-[A-Za-z0-9_-]+\.js'
ls dist/assets/index-*.js   # the two should match after a deploy
```

## What Vercel handles for you
- **SPA fallback** — framework preset rewrites unknown routes to `index.html`.
- **Serverless** — `api/feedback.ts` runs on Fluid Compute, no config.
- **Headers/CSP** — from `vercel.json` (CSP is enforced).
- **Preview URLs** — one per PR/branch.

## Env vars
Set the optional sync keys (build-time, inlined):
```bash
vercel env add VITE_SUPABASE_URL production
vercel env add VITE_SUPABASE_ANON_KEY production
```
For the feedback function (runtime): `GITHUB_TOKEN` (+ optional `GITHUB_REPO`).

## Gotchas
- A stale PWA service worker can mask an update — hard-refresh (`Ctrl/Cmd+Shift+R`) to verify a deploy.
- `VITE_*` changes require a **rebuild** to take effect (not a runtime restart).
